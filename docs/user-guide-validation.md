- Этот отчёт: источники, метод проверки и ограничения достоверности.

## Метод и границы проверки

Выполнено чтение текущих исходных текстов интерфейса и серверных обработчиков, финансовых функций, проверок доступа, правил актуальности расчётов и закрытия. Точные подписи сверены с компонентами и определениями форм. Это **статическая сверка**, а не новая браузерная приёмка и не подтверждение исполнения всех сценариев.

В рамках этой задачи не выполнялись вход в приложение, создание сеансов, финансовые операции, запросы на изменение данных или выгрузка новых отчётов. Даже обычный вход создаёт запись сеанса, поэтому для соблюдения запрета на изменения базы он не использовался. Microsoft Excel не запускался. Существующие результаты прошлых этапов не объявляются заново выполненными проверками.

Автоматические тесты приложения, HTTP-проверки, TypeScript и production build **не запускались**: задача ограничена документацией. Результат проверки руководства нельзя трактовать как успешный прогон тестов или разрешение запуска production. Логины и персональное распределение обязанностей взяты из утверждённого задания; актуальность пяти аккаунтов в работающей базе повторно не проверялась.

Назначение Атабека основным проектным оператором, Катерины — финансовым, Собира — контролирующим является **рекомендуемым внутренним регламентом из задания**. В приложении нет обязательного разделения «вводит один — утверждает другой». В руководстве это оговорено, чтобы не приписывать системе несуществующее ограничение.

## Сопоставленные финансовые правила

| Правило в руководстве | Основание и результат чтения |
| --- | --- |
| Заработок = фактические часы × историческая ставка | `calculations.ts:17`, обработчик работы: используется сохранённая ставка; плановые часы не заменяют фактические |
| КТУ 30% текущего заработка | `calculations.ts:43`: КТУ рассчитывается до добавления положительного переноса |
| Квартальная база и зарплата | `calculation-data.ts:25`: действительные выплаты типа фиксированной зарплаты выбираются по расчётным месяцам; история оклада не считается фактической выплатой |
| Половины сохраняют сумму | `calculations.ts:26`: премия округляется до 4 знаков по `ROUND_HALF_UP`, перенос — остаток от положительной разницы; отрицательный результат не создаёт долг |
| Источник переноса | `workflows.ts:1538`: предыдущая версия должна быть принятой и актуальной; сохраняется ссылка на неё |
| Итог сотрудника без повторного переноса | `calculations.ts:63`, `calculations.ts:76`: заработок + КТУ − подходящие выплаты, возмещения исключены; окончательная положительная выплата отдельно округляется до целых UZS |
| Различие категорий | Единый `compensationEligible`: зарплата, бонус, итог включаются; возмещение исключено; прочая выплата зависит от сохранённого признака |
| Партнёрский расчёт по проекту и сезону | `calculations.ts:144`, `calculation-data.ts:115`: положительные базы, двухступенчатое распределение общих затрат, сохранение нулевых/отрицательных строк, фиксированная проектная ставка |
| Партнёрский остаток | `versions.ts:107`: округлённое принятое обязательство минус действительные отнесённые выплаты; разница округления хранится отдельно; отменённые не входят |
| Все партнёры оплачены до закрытия | `versions.ts:161` и `calculation-data.ts:182`: непогашенный остаток, переплата, неотнесённые платежи и неактуальное распределение блокируют |
| Стоимость обналичивания | `calculations.ts:212`, обработчик `cashout`: списание банка минус фактическая касса; распределение сохраняет сумму, отдельно повторять расход нельзя |
| Деньги и поездки | `trip-payments.ts`: фактические выплаты/возвраты отдельно от признанного расхода; историческая неполнота и остатки видимы |
| Остатки на дату и сверка | `calculation-data.ts`, `reconcileCash`: ожидаемый остаток по журналу, проверка на конец сезона, объяснение не создаёт скрытую корректировку |
| Актуальность одобрений | `versions.ts`, `calculation-data.ts:186`: подтверждения привязаны к состоянию источников и выбранным расчётам; история не суммируется как текущий итог |
| Подтверждённый Excel | `season-report.ts:332`: в открытом сезоне требуется готовность закрытия; в закрытом — сохранённый снимок с проверкой целостности |

В этой таблице короткое имя файла `calculations.ts` означает `src/domain/calculations.ts`; остальные серверные файлы находятся в `src/server/`. Результат — соответствие объяснения текущему коду, **не новая независимая финансовая сертификация**. Учебные числа в руководстве иллюстративны, не реальные ставки компании.

## Отличия от упрощённых ожиданий, отражённые в тексте

1. Реальная кнопка проекта — «Новый проект», а не «Создать проект»; создание имеет два шага с выбором разделов.
2. В международном каталоге D01 — правоустанавливающие документы, D02 — основные средства. Пример исправлен по справочнику; все 66 шаблонов не дублировались.
3. Отдельной кнопки закрытия месяца нет. Месячный список — организационная проверка.
4. Сотрудник просматривает свою работу, но ввод выполняет руководство.
5. Создание аккаунта сотрудника/партнёра автоматически создаёт профиль. Выбор уже существующего профиля в форме отсутствует, хотя серверная операция поддерживает соответствующую привязку; руководство не направляет пользователя к прямому изменению базы.
6. Флажок активности есть при изменении, не при создании аккаунта. Новый аккаунт активен. Ограничена смена роли связанного профиля; защищён последний активный руководитель.
7. Доход/расход без указанного счёта не создаёт движения денег. Универсальный простой пользовательский маршрут последующей оплаты такого документа не заявлен; запрещена рекомендация повторно признать доход/расход.
8. Командировка через границу сезона отклоняется до решения политики распределения. Наличие полей для частей обычного расхода не объявлено механизмом автоматического разделения поездки.
9. Принятие, расчёт и выплата — отдельные шаги; после итоговой выплаты сотруднику требуется актуализировать сезонный результат. При смене принятого партнёрского начисления проверяют отнесение существующих платежей.
10. Подтверждённый отчёт может быть доступен до фактического закрытия, если выполнены все условия. Для закрытого сезона используется сохранённый снимок.
11. В текущей проверке кассы требуется хотя бы один кассовый счёт с движением. Сезон без наличных передаётся на рассмотрение; фиктивное движение не предлагается.
12. Отмена поездки сама по себе не означает автоматической отмены всех связанных платежей или реального возврата денег.

## Редакторская проверка и ограничения

Проверка файлов командой PowerShell выполнена после записи документов: основное руководство содержит ровно 25 разделов в последовательности 1–25; проверены все 10 относительных ссылок между четырьмя документами — отсутствующих файлов нет; символов повреждённой кодировки не обнаружено. Быстрый старт содержит 1 158 слов по подсчёту непустых последовательностей, что соответствует компактному тексту для памятки; печатная вёрстка не выполнялась. Поиск внутренних названий `WorkEntry`, `SettlementSource`, `AllocationRun`, `Prisma`, `PostgreSQL`, `API` и путей `src/` в трёх пользовательских документах совпадений не дал.

Выполнен самостоятельный разбор инструкций как для нового пользователя: создание нового сотрудника без дубликата; проект → раздел → назначение → работа; поездка → расход → выдача/возврат; квартал → принятие → выплата; сезон → обновление расчёта → сверка; партнёрская выплата и округление; забытый пароль; недоступный подтверждённый отчёт. Это проверка последовательности текста по реализации, не исполнение операций.

Исправлена найденная при сверке неточность: активность аккаунта нельзя выбирать в форме создания, она меняется после создания. Во всех памятках сохранено различие между подтверждённым фактом платежа и расчётным начислением, между пользовательским регламентом и техническими правами.

Остаются непроверенными в этой задаче: реальный вход каждой роли, визуальная компоновка страниц в конкретном браузере, нативные подтверждения, физическое скачивание XLSX, открытие в Microsoft Excel, текущее состояние рабочей базы, наличие и восстановимость актуальных резервных копий. Ответственный за сопровождение и место хранения копий должны быть назначены компанией.

Документы готовы как инструкции по текущей реализации с перечисленными ограничениями. Они не одобряют старые расчёты и не заменяют приёмку реальных данных или финансовую сверку перед закрытием сезона.
