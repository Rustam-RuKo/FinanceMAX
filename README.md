# FinanceMAX

Русскоязычная система управления финансами аудиторской компании: проекты и разделы аудита, рабочее время, исторические ставки, выплаты, командировки, банк и касса, расчёты сотрудников и партнёров, сверка сезона и Excel. Начисления, фактические выплаты и принятые версии расчётов учитываются отдельно.

Репозиторий предназначен **только для PRIVATE GitHub**. Поле `private` в package.json запрещает случайную публикацию npm-пакета, но не задаёт видимость GitHub. Создание репозитория, первый commit и отправка требуют отдельного разрешения.

## Стек и требования

Node.js 22, npm, PostgreSQL 18; Next.js 16, React 19, TypeScript, Prisma 6, Decimal.js, ExcelJS. Точные версии зависимостей закреплены в package-lock.json. Нужны отдельная база разработки и отдельный тестовый PostgreSQL. У runtime-пользователя должны быть ограниченные права, у миграционного — права управления схемой. Настройка ролей и рабочего размещения выполняется по отдельному согласованному регламенту.

## Установка и окружение

```powershell
npm ci
Copy-Item .env.example .env
```

Заполните локальный `.env` собственными значениями. Шаблон содержит только placeholders; запуск с ними невозможен.

| Переменная | Назначение |
| --- | --- |
| DATABASE_URL | Подключение приложения с ограниченными правами |
| MIGRATION_DATABASE_URL | Подключение для миграций; не выдавать пользователям приложения |
| APP_ORIGIN | Точный origin локального приложения, включая схему и порт |
| TRUST_PROXY | false, пока доверенный прокси не настроен отдельно |
| FINANCEMAX_ENV | development для разработки; demo только для отдельной демонстрационной базы; production для рабочего окружения |
| ADMIN_EMAIL, ADMIN_NAME, ADMIN_PASSWORD | Однократное создание первого администратора пустой базы; после этого убрать |
| DEMO_PASSWORD | Необязательное значение для изолированного demo; иначе пароль генерируется |
| PRODUCTION_DATABASE_URL, PRODUCTION_SOURCE_DATABASE_URL | Специальный первичный перенос согласованных пользователей и справочников, не обычная установка |
| PG_BIN | Необязательный путь к инструментам PostgreSQL для обслуживания |
| TEST_FILE, TEST_DATABASE_NAME, PHASE6_BROWSER | Служебные параметры тестового стенда; при обычной работе оставить пустыми |

Next.js управляет NODE_ENV. Приложение не использует SESSION_SECRET или AUTH_SECRET: сессионные токены генерируются случайно, в базе сохраняются их хеши. Секреты, `.env`, runtime-файлы, резервные копии и сформированные отчёты не публикуются.

## Миграции и первый вход

После создания **отдельной базы разработки** и настройки подключений:

```powershell
npm run db:generate
npm run db:validate
npm run db:migrate
```

Миграции находятся в prisma/migrations и должны входить в репозиторий, хотя обычные SQL-дампы исключены. Не используйте schema push/reset для рабочей базы. Перед изменением существующей рабочей схемы нужны резервная копия, проверенное восстановление и просмотр diff.

Для пустой базы задайте ADMIN_* через защищённое окружение и отдельно выполните `npm run db:admin`. Это создаёт пользователя, а не запускает демонстрационные операции. После первого входа используйте управление аккаунтами в интерфейсе.

`seed:production`, `bootstrap:production-users` и `db:runtime` — специальные административные процедуры, **не часть установки, сборки или запуска**. Production seed ограничен явно указанной целевой production-базой и архивным источником; bootstrap аккаунтов требует локального проверенного manifest. Эти процедуры нельзя запускать автоматически или использовать как универсальный seed чистого клона.

## Разработка и сборка

```powershell
npm run dev
```

Откройте адрес локального сервера с origin, совпадающим с APP_ORIGIN. Для подготовки сборки:

```powershell
npm run typecheck
npm run build
npm start
```

На чистой установке с ещё не созданными типами маршрутов сначала можно выполнить `npx next typegen`, затем typecheck. Сборка также генерирует типы. На Windows генерация Prisma может требовать остановки процесса, использующего его DLL.

Это команды приложения, а не утверждённый план размещения в офисе. Успешная сборка не заменяет финансовую приёмку, резервирование и настройку защищённого доступа.

## Проверки

```powershell
npm run test:housekeeping
npm run test:unit
npm test
npm run test:http
```

Housekeeping проверяет защитные условия подготовительных процедур; unit — финансовые функции и ограничения доступа. `npm test` запускает сборку и TypeScript-наборы, включая интеграцию и HTTP. Набор housekeeping запускается отдельно. `test:http` запускает HTTP-набор отдельно.

**Полные тесты допускаются только на отдельном одноразовом PostgreSQL-кластере.** MIGRATION_DATABASE_URL должен указывать на него; тестовый пользователь создаёт и удаляет базы/роли. Текущий harness использует заданное подключение, поэтому одних случайных имён создаваемых баз недостаточно для защиты рабочего кластера. Перед запуском проверьте адрес назначения. Production URL для тестов не задавайте.

Для тестового стенда создайте пустой каталог `.runtime` (`New-Item -ItemType Directory -Force .runtime` в PowerShell). Harness записывает туда диагностику; старые runtime-файлы для тестов не нужны. Не используйте учётные записи и данные компании как fixtures.

## Демонстрационная база

Demo seed запускается только при FINANCEMAX_ENV=demo, явном --demo (его передаёт `npm run seed:demo`) и отдельной локальной базе `financemax_demo` либо `financemax_demo_<идентификатор>`. Production NODE_ENV и основной рабочий адрес запрещены. Сначала применяются миграции в этой отдельной базе. Демонстрационный пароль берётся из окружения или генерируется; результат сохраняется только в исключённой `.runtime`.
